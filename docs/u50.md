# From RTL to inference on the Alveo U50

This flow creates a Vitis RTL kernel (`.xo`), links it against the matching
U50 development platform (`.xclbin`) and loads it through XRT. An XO alone
cannot run on the card. The flow loads the dynamic user region.

An [unattended build and verification run on a Linux build machine](unattended_u50.md)
is available for all three references, including resume and result logs.

## 1. Prepare the environment

You need an Alveo U50 with a matching base shell installed, Linux, Vivado/Vitis
with U50 device support and a suitable license, the development platform,
XRT with drivers, Python 3.11+ and a C++17 compiler. Simulation also requires
Icarus Verilog and Verilator.

Previously used: Vivado/Vitis 2026.1, XRT 2.23.244,
`xilinx_u50_gen3x16_xdma_5_202210_1` and
`xilinx_u50_gen3x16_xdma_base_5`. These details document the tested setup,
not every possible combination. Use your own installation paths, license
and device index.

Activate Vivado and Vitis using their installed `settings64.sh` files.
XRT is often installed in `/opt/xilinx/xrt`; set `XILINX_XRT` if it differs.
`XILINXD_LICENSE_FILE` can point to your license file or license server.
License files do not belong in the repository.

```bash
source "${XILINX_XRT:-/opt/xilinx/xrt}/setup.sh"
bash deploy/u50/inspect_host.sh
python tools/run_checks.py
```

The inventory shows the card, XRT and installed platforms. A U50LV or another
board requires its own matching part and a validated configuration; do not
blindly reuse the U50 defaults.

## 2. Build a reference

Start with LIF. This preparatory command prints the explicit parameters
without starting a build tool:

```bash
python tools/build_reference.py lif --print-only
```

Set `PLATFORM` to the full path of your matching `.xpfm` and build:

```bash
PLATFORM=/path/to/installed/u50_platform.xpfm
python tools/build_reference.py lif --mode xclbin --platform "$PLATFORM"
```

Output: `build/reference/lif/artifacts/snn_accelerator.xclbin`.
For `izh` and `hh`, use the same command with the corresponding variant name.
Explicit parameters come from `configs/references.json`; the scripts use
one executor per layer and interface 1.6. The Linux link script sets the
kernel clock to 100 MHz.

Clock adapter replacement is disabled by default. For the tested combination
of **Vivado/Vitis 2026.1** and **`xilinx_u50_gen3x16_xdma_5_202210_1`**, it
was required for all three reference models and tested on the U50 on
2026-09-23. Enable it explicitly:

```bash
LEGACY_U50_CLOCK_ADAPTER_COMPAT=1 python tools/build_reference.py lif \
  --mode xclbin --platform "$PLATFORM"
```

Without this option, normal linking proceeds without replacing files.
Other platform/tool combinations have not been validated by these tests.
The replacement in `deploy/u50/compat/` is licensed under CERN-OHL-S-2.0;
see [provenance and use](clock_adapter.md). No AMD confirmation is available;
this absence is not treated as an established prohibition.
After linking, check timing/routing results and record the XCLBIN, source
revision, tool version and platform ID together.

Optionally, an XO can be packaged on Windows:

```powershell
./tools/build_u50.ps1 -Mode xo -HiddenNeuronModel lif -OutputNeuronModel lif `
  -HiddenExecutorCount 1 -OutputExecutorCount 1 -InterfaceMinor 6 `
  -VivadoPath 'C:/your/Vivado/bin/vivado.bat' `
  -LicensePath 'C:/your/license/Xilinx.lic'
```

The Linux flow described above is the reference linking flow. The standalone
PowerShell linking option does not include the Linux compatibility handling.

## 3. Check the host software and model

```bash
bash deploy/u50/install_local.sh
export PATH="$HOME/.local/bin:$PATH"
export PYTHONPATH="$PWD/python${PYTHONPATH:+:$PYTHONPATH}"
python tools/check_reference.py
```

The host software requires no PyTorch installation for inference. The C++
helper `xrt-register-server` handles register accesses. The Python check
verifies weight files and six synthetic reference cases without an FPGA.

## 4. Load the card and run an example

```bash
XCLBIN="$PWD/build/reference/lif/artifacts/snn_accelerator.xclbin"
DEVICE=0   # use the index from your XRT inventory
MODEL="$PWD/results/full-encoding-50epoch-2026-09-11/models/lif__deterministic-rate__scale1__s14"
python -m snn_host --xrt-xclbin "$XCLBIN" --xrt-device "$DEVICE" probe > build/probe_lif.json
python deploy/u50/validate_snn_probe.py lif build/probe_lif.json
python -m snn_host --xrt-xclbin "$XCLBIN" --xrt-device "$DEVICE" upload-model "$MODEL"
python -m snn_host --xrt-xclbin "$XCLBIN" --xrt-device "$DEVICE" --timeout 60 \
  infer "$MODEL" examples/vertical_bar.raw
```

The probe expects `SNN1`, interface 1.6, dimensions 784/256/10, capacity
12,544 and executor counts 1/1. The model must match both reported neuron
models. Upload verifies 203,264 weight bytes and CRC. For the bar pattern,
the expected Python prediction is **1**; for `examples/blank.raw`, it is
**null**. Both patterns were generated within the project and have no MNIST
ground-truth label. By default, `infer` uploads the model itself; separate
commands do not require a persistent host connection.

## 5. Qualify MNIST inference

The four MNIST IDX hashes and dataset split are documented in
`results/full-encoding-50epoch-2026-09-11/dataset.json`. Obtain the data
separately as described in the [training guide](training.md). `IMAGES` and
`LABELS` are the extracted test files in `data/MNIST/raw/`.

```bash
IMAGES=data/MNIST/raw/t10k-images-idx3-ubyte
LABELS=data/MNIST/raw/t10k-labels-idx1-ubyte
python -m snn_host --xrt-xclbin "$XCLBIN" --xrt-device "$DEVICE" --timeout 60 \
  qualify "$MODEL" "$IMAGES" "$LABELS" --samples 10
python -m snn_host --xrt-xclbin "$XCLBIN" --xrt-device "$DEVICE" --timeout 60 \
  mnist "$MODEL" "$IMAGES" "$LABELS" --samples 10000
```

The gate requires zero differing **predictions** against the fixed-point
reference. It does not automatically prove equality of all internal states.
For a release, archive model hashes, XCLBIN hash, probe, gate, full test and
platform inventory together. Historical accuracies do not automatically
apply to a newly built artifact.

## Troubleshooting

| Error | Check |
|---|---|
| Part not found / BASIC license insufficient | U50 device installation and your license activation |
| Platform missing | Correct XPFM path and matching shell version |
| Clock adapter error | Intended Linux linking flow and exact platform match |
| XRT helper fails to start | XRT environment, libraries, device index and kernel name |
| Model/register mismatch | Correct LIF/IZH/HH XCLBIN, interface, dimensions and parameters |
| Gate mismatch | Compare weight/artifact hashes, encoding, sample index and T |

The host transfers events serially over AXI4-Lite. Its runtimes are not
DMA/HBM throughput measurements. The passively cooled U50 requires suitable
airflow.
